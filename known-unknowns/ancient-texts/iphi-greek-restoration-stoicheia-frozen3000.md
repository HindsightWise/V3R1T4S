# Greek inscriptions: beat Stoicheia v2 (CER 15.5, top-1 74.5) on the frozen 3,000-gap file cut from Ithaca's PHI-digit-3 test split

🏺 **Ancient texts and fragments** · standard · tractability ★★☆☆☆ · compute: laptop-days (a GPU helps; fine-tuning or reranking with a ~400M-parameter character model); test file 2.9 MB, public Greek corpora a few GB · open as of 2026-10-30

## The problem

Ithaca (Assael, Sommerschield, Shillingford, Bordbar, Pavlopoulos, Chatzipanagiotou, Androutsopoulos, Prag and de Freitas, Nature 2022) fixed the standard split for Greek epigraphic restoration: I.PHI inscriptions whose PHI id ends in 3 are test, 4 validation. Its masked test set was never released (Locaputo, Brunello, Saccomanno, Platanou and Serra, 'Ithaca Revisited', LREC 2026, aclanthology 2026.lrec-1.82, recompute Ithaca on their own masks for that reason), so CERs printed in different papers are not comparable. Cullhed and Thorn Cleland (Stoicheia, arXiv 2608.07249v1, 7 Aug 2026; code github.com/ericu9500/stoicheia, Apache-2.0, HEAD 1870b871 of 2026-08-03) ship a frozen sample file, insc/eval/frozen/strict_test_fold3_samples.json (2,936,335 bytes, git blob 54062823f79f, sha256 4373df905922785094688153462dd524cab2e8216a33a0673cbf0b5b35a1004a): 3,000 artificial gaps, 300 at each length L = 1..10, cut from 375 decontaminated digit-3 inscriptions; each record is {phi_id, L, start, gold, text}, the whole inscription is context with its real lacunae left as '-' runs, and spaces count inside the gap (1,896 of the 3,000 golds contain a space). On this file, beam 20, Levenshtein CER over the gap string (insc/eval/restore_strict.py), their Table 2 reports CER / top-1 / top-20 (%): Ithaca 24.6 / 63.0 / 74.9; the 2025 Aeneas-framework Greek release 23.5 / 64.0 / 75.5; Stoicheia v1 17.0 / 72.0 / 80.8; Stoicheia v2 15.5 / 74.5 / 81.7 (a 405M-parameter character-level masked-diffusion encoder; the digit-3 checkpoint Ericu950/Stoicheia-restoration-test3 is public on Hugging Face). Apollo Restore (McGovern, Dolganov, Belkadi, Kunsch, Vlitas and Smith, arXiv 2609.22455v4, 7 Oct 2026; 24B, fill-in-the-middle) reports large top-20 gains on its own IG / DDB / DCLP benchmarks, but has not released weights or benchmark ('We will release the weights, data, and evaluation code') and does not report on this file. Status 2026-10-28: no result on the frozen file other than Stoicheia's Table 2 was found; arXiv 2608.07249 is still at v1 and the repository is unchanged since 2026-08-03. Ithaca's beam search was fixed upstream on 2026-10-27 (google-deepmind/ithaca cd4e47bc: deduplication kept the lower-scoring copy of a duplicate hypothesis, and punctuation could fill a gap), and predictingthepast's on 2026-10-21 (c8889e9c), so the Ithaca and Aeneas rows of Table 2 were produced before those fixes.

## What counts as a win

A frozen prediction file covering all 3,000 records of strict_test_fold3_samples.json (git blob 54062823f79f), with up to 20 ranked candidate strings per record, each exactly L characters long over the characters that occur in the file (the 24 unaccented lower-case Greek letters with sigma merged, space, '.' and '0'), whose hash is committed before scoring, must score CER strictly below 15.5 AND top-1 strictly above 74.5 (percent; Stoicheia v2, Table 2 of arXiv 2608.07249, re-read immediately before claiming). CER = mean over records of Levenshtein(candidate 1, gold) / L, which equals the mean of the per-length means because every length has 300 records; top-1 = exact match of candidate 1 with gold, spaces included. Conditions: (a) for each record the model reads only that record's text with text[start:start+L] hidden; no other record, metadata or id lookup; (b) no training, tuning or retrieval material contains a test inscription (phi_id in the file) or a near-duplicate of one: same normalised text, Jaccard similarity of normalised character 5-gram sets of at least 0.5, or a shared run of 100 or more consecutive normalised characters; (c) every source of training and pretraining text is public and listed with hashes so that (b) can be checked; material inherited from a released Stoicheia checkpoint counts as decontaminated by its authors' fold manifests, everything the claimant adds is scanned; models whose pretraining data is undisclosed cannot claim the full win.

## Partial wins

- **p1:** Same file and conditions: CER strictly below 15.5 or top-1 strictly above 74.5 (only one of the two), with the other metric no worse than Stoicheia v1 (17.0 CER, 72.0 top-1).
- **p2:** Long gaps: on the 1,500 records with L = 6..10, mean CER and top-1 both strictly better than Stoicheia v2 on the same records, where the Stoicheia v2 predictions are regenerated by the claimant from the released Ericu950/Stoicheia-restoration-test3 checkpoint with the repository harness (beam 20, INSC_TEST_DIGIT=3) and published as a frozen file (hash committed before scoring); the verifier re-runs a random 100 of those records to confirm them.

## How a win is checked

The verifier fetches the frozen file at commit 1870b871 and checks its blob id and sha256, checks the prediction file's hash against the pre-scoring commitment, and rescores CER, top-1 and top-20 both with independent code (Levenshtein over the L-character gap strings, sigma folded, spaces counted) and with the scoring loop of insc/eval/restore_strict.py. It then scans the published training manifest for the 375 test phi_ids and for near-duplicates of their texts (identical text, 5-gram Jaccard at least 0.5, shared runs of 100 characters) with a rolling-hash pass. Rescoring takes seconds and the scan under an hour; the verifier never retrains.

## Ideas to start from

Starting points, not instructions. The best wins came from angles nobody listed.

- Rerank Stoicheia v2's 20-best: its top-20 (81.7) is 7.2 points above its top-1 (74.5), so a second scorer (a right-to-left or fill-in-the-middle character model trained on the same decontaminated public corpora) can win top-1 without a better generator.
- Retrieval of formulae from the training digits (not 3 or 4): decrees, dedications and epitaphs repeat long phrases, and a parallel passage often fixes a whole gap; keep the near-duplicate filter on the retrieval index too.
- Length-exact, segmentation-aware decoding: the gold is exactly L characters including spaces, so enumerate word divisions inside the gap rather than letters alone, as Stoicheia's boundary plane does.
- Report the letters-only CER that the harness also computes (spaces stripped from both strings); about 15% of gap characters are spaces, which are easier than letters.
- If you report Ithaca or Aeneas baselines, re-run them with decoders at or after google-deepmind/ithaca cd4e47bc and predictingthepast c8889e9c and record the commits.

## Traps

False wins others have fallen for. A claim that walks into one of these will not survive the skeptics.

- The gold is embedded in each record's text (text[start:start+L] == gold for all 3,000 records): mask it before any model sees the text, and never let a model read the raw file.
- The 3,000 gaps come from only 375 inscriptions (about 8 per inscription), so gaps are not independent; use paired tests that resample inscriptions, not gaps.
- The file covers only the decontaminated part of the digit-3 split (the harness excludes test inscriptions flagged as contaminated), so its numbers are not comparable with Ithaca's printed 26.3 CER (Nature 2022, Table 1) or with Apollo Restore's IG numbers.
- Table 2's Ithaca and Aeneas rows predate the upstream beam-search fixes of 2026-10-21 and 2026-10-27; re-runs with current code can give different baselines.
- PHI texts are on the open web: a model with undisclosed pretraining may have read the test inscriptions and their editors' restorations, which is why such models cannot claim the full win.
- PHI can hold several editions of one stone under different ids, so a split by id alone leaks; the near-duplicate rule in (b) is part of the criterion.
- Candidates must be exactly L characters: generators that do not know the length (Ithaca's no-count mode, FIM decoders without a hint) must be truncated or filtered consistently, or they lose exact matches.
- 55 of the 3,000 golds contain '.' (48) or the numeral placeholder '0' (7); decoders that emit only letters and spaces (Stoicheia's renderer, Ithaca after cd4e47bc) can never match those exactly, so a system that can emit them has a small built-in edge.
- Released checkpoints are Python pickles or remote-code model classes; load them only in a sandbox.
