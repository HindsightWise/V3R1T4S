# Smallest order with exactly 33 groups (OEIS A046057 a(33), the first unknown moa)

🃏 **Wildcard** · standard · tractability ★★★☆☆ · compute: laptop-days (GAP: Holder formula, CubeFree package and GrpConst over roughly 100k orders) · open as of 2026-10-30

## The problem

moa(k) is the smallest order m with exactly k groups of order m (Conway, Dietrich and O'Brien (CDO), Math. Intelligencer 2008; OEIS A046057, data a(1..32), a(32) = 630). a(33) is unknown; OEIS still gives only a(33) > 30500 (M. A. Asiru, 2017), and CDO's Table 2 guesses 163293. Two facts tighten this, both re-runnable from public data (checked 2026-10-30). First, Max Horn's table at groups.quendi.de has no known order n <= 50,000 with gnu(n) = 33, and every order <= 50,000 that the table leaves unknown has a proper divisor d with gnu(d) >= 1181. Since gnu(n) >= gnu(d) for d | n (take G x C_(n/d)), a(33) > 50,000. Second, Hölder's formula gives gnu(163293) = 33 with 163293 = 3*13*53*79, the smallest squarefree order with 33 groups. So 50,000 < a(33) <= 163,293. CDO report computing gnu(n) with the CubeFree package for the cubefree n in [2048, 163293] whose lower bounds were at most 30. The main remaining work is the non-cubefree orders in range (7,686 are not ruled out by the divisor bound alone), plus any cubefree orders that computation did not cover. Later unknown terms include a(65), a(82), a(95) and a(107): no order <= 50,000 has 65, 82, 95 or 107 groups.

## What counts as a win

Success means the exact value of a(33), with: (i) an order m and a re-runnable certificate that gnu(m) = 33, and (ii) a re-runnable certificate that gnu(n) != 33 for every n < m. For (ii), an exact count, or a lower bound > 33 from a divisor or an explicit list of 34 pairwise non-isomorphic groups, is enough for each n. The value must be <= 163,293, which already has 33 groups, and > 50,000. Either a(33) = 163,293 or a smaller order beats the CDO guess; both count.

## Partial wins

- **p1:** A re-runnable certificate that gnu(n) != 33 for every n <= 100,000 (giving a(33) > 100,000).
- **p2:** An order m < 163,293 with gnu(m) = 33, certified by two independent methods (for example GrpConst or a Frattini-extension count cross-checked against CubeFree or SmallGroups-style enumeration).

## How a win is checked

Re-run the released script: squarefree orders by Hölder's formula, cubefree orders by GAP CubeFree, the rest by GrpConst or SmallGroups. Divisor lower bounds are taken from the table values and checked by recomputation. Spot-check the pipeline against Horn's table for n <= 50,000 and the known moa values a(22) = 6321 and a(31) = 11774.

## Traps

False wins others have fallen for. A claim that walks into one of these will not survive the skeptics.

- Horn's JSON stores [non-solvable, solvable] counts per order; the total is their sum.
- gnu(n) >= gnu(d) for d | n relies on Krull-Remak-Schmidt cancellation (G x C_m determines G); do not use it with other constructions without proof.
